# 钢球检测 UART 诊断

开发板使用板载 USB-UART Type-C 接口，FPGA TX 为 H1。烧录新 bit 后，将 USB-UART 接到电脑，串口设置为 115200、8 数据位、无校验、1 停止位。它与下载 bit 的 USB-JTAG 接口不同。

在 PowerShell 中运行：

```powershell
[System.IO.Ports.SerialPort]::GetPortNames()
powershell -ExecutionPolicy Bypass -File "D:\AAAProject\FPGA\HX1P35A_Contest_202606\exercise\lab_hd_1_mipi_hdmi_1080p_steel_ball\steel_ball_verification\capture_uart.ps1" -Port COM5 -Seconds 30
```

将 `COM5` 换成实际端口。脚本同时显示诊断结论并保存带时间戳的 `uart_capture_*.log`。串口调试助手也能直接看每帧一行的 ASCII 文本。

示例：

```text
F=07BC R=00012E A=0000F2 P=000244 X=659-6F2 Y=072-0F9 G=D N=004 Q=00000 S=05 E=0 V=05EEC0 T=438 D=07BC L=438 B=6A5-0B5 C=01 F=08
```

| 字段 | 含义 |
| --- | --- |
| `F` | ISP 帧开始采样序号，十六进制，循环计数 |
| `R` | 原始红色掩码像素数（全帧），十六进制 |
| `A`、`P` | 选中红簇的像素数、其包围框周长估算值 `2(W+H)` |
| `X`、`Y` | 选中红簇包围框的最小与最大坐标（不是全帧极值） |
| `G` | 几何检查位：bit0 面积、bit1 主簇占比（选中簇 ≥ 已聚类红像素总数的 `DOMINANCE_PERCENT`，当前顶层为 40%）、bit2 宽高比、bit3 尺寸紧凑；`F` 表示四项通过 |
| `N` | 当前活动红簇个数（空间聚类结果，上限 4） |
| `Q` | 兼容字段，当前无输入 FIFO，固定为 0 |
| `S` | bit0 红像素指示，bit1 帧命中（几何四项通过），bit2 候选框有效，bit3 确认球（绿色框），bit4 坏帧，bit5/bit6 固定为 0，bit7 一秒内没有新的 ISP 帧开始 |
| `E` | 最近完成帧的格式错误：0 无，3 帧格式错误 |
| `V` | 上一 ISP 帧的 128 位有效字数；1920×1080 正常为 388800（05EEC0） |
| `T` | 上一 ISP 帧的行结束数；正常为 1080（438） |
| `D` | 检测器累计完成帧数；它与 `F` 一起判断输入和检测器是否持续运行 |
| `L` | 检测器当前处理的行数；完整帧应到 1080（438） |
| `B` | **球心坐标** `xxx-yyy`（选中簇红像素重心，`sum/cnt`）；无候选时为 `000-000` |
| `C` | 有效性位：bit0 候选有效（对应琥珀框），bit1 确认球有效（对应绿框）；无目标时为 `00` |
| `F` | 置信度：`00` 无目标，`04` 有候选但未确认，`08` 几何通过待连帧，`0F` 确认 |

检测器逐 token 做在线空间聚类，最多跟踪 4 个红簇：token 按“到红簇包围框的距离”（默认 16 px）归并，距离画面边框 4 px 内的像素被忽略。帧末用 4 拍扫描选出像素最多的红簇作为候选，再用逐拍除法得到簇内红像素重心 `(sum/cnt)` 作为**球心**，并做面积、主簇占比、宽高比、尺寸紧凑四项几何检查。**填充率不再作为确认门槛**：稀疏红掩码（球本体只有边缘/高光呈红色）会让填充率天然低到 1% 量级，继续用填充率只会拒绝真实目标；主簇占比 + 宽高比 + 尺寸 + 连续帧跳变约束才是可靠确认依据。

`S` 的 bit2 为 1 表示已有候选红簇（HDMI 画琥珀色框，框以球心为中心），bit1 为 1 表示几何四项通过，bit3 为 1 表示已连续 `CONFIRM_FRAMES` 帧确认且相邻帧球心位移未超过 `MAX_JUMP`（HDMI 画绿色框）。当前顶层允许候选红簇宽高最多 400 px；显示框按红簇较大的宽或高自动调整，半宽限制在 64–192 px，再按画面边缘裁剪。无目标时 `A=P=0`、`G=0`、`B=000-000`、`C=00`、`F=00`，不会残留旧值。

**控制端约定**：闭环只使用 `C` 的 bit1（确认有效）为真时的 `B` 坐标；可选用 `S` 的 bit3 或 `F=0F` 作为同一判据。确认无效（目标消失、跳变过大、几何不符、坏帧）时应停止驱动或让执行器回到安全中位，不要使用 `X/Y`（那是包围框边界，不是球心），也不要在 `C` bit1 为 0 时使用 `B`。目标重新进入时需重新累计 `CONFIRM_FRAMES` 帧才会重新置绿。

若 `R` 较大但 `G` 不是 `F`，可按 `G` 的失败位排查：bit0 面积过小/过大，bit1 主簇占比不足（有多个竞争红物体或红掩码被拆散），bit2 形状过扁/过长，bit3 尺寸超出 `MAX_DIM`（多为杂点链式合并）。`F` 持续增加而 `D` 不增加表示 ISP 仍送帧、检测器未完成处理；`F` 不增加且 `S` 的 bit7 为 1 表示没有新的 ISP 帧开始。画面中存在多个红物体时，检测器选择像素最多的红簇，并用上一帧位置约束（超限跳变则该帧不确认）。UART 由板载 50 MHz 系统时钟驱动，与摄像头数据时钟独立。
